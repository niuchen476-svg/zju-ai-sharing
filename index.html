01 / TERMS

一张表，把常见术语说清楚

术语
一句话解释

Model
负责理解和生成内容的底层模型。
GPT、Claude、Gemini、DeepSeek、Qwen
Product
把模型包装成普通人可以直接使用的产品。
ChatGPT、Claude、豆包、元宝、Kimi
Agent
能围绕目标规划步骤、调用工具并继续执行的 AI 系统。
研究助手、编程助手、自动化工作流
Tool
让 AI 能搜索、读写文件、运行代码或操作网页。
联网搜索、Python、浏览器、文件系统
Skill
教 AI 用固定方法完成某一类任务的说明与资源包。
制作 PPT、分析表格、检查代码
MCP
让 AI 用统一方式连接外部工具与数据的协议。
连接 GitHub、Notion、数据库和本地服务
Loop
执行、检查、修改、再执行，直到达到目标。
生成初稿 → 验证 → 修正 → 再验证
Harness
承载 Agent 的运行环境、权限、上下文、测试和反馈机制。
Codex、Claude Code 等工具背后的工作框架
OpenClaw
一个具体的开源 Agent 网关项目，不是通用技术类别。
把聊天入口、模型与本地工具连接起来

03 / PRACTICE · 01 BRIEF

第一步：我没有教它写代码

我提供材料
给出原始公众号链接、完整文字和配图，而不是只说“做个网页”。
我定义结果
明确安全主题、预警等级、三个阶段、内容来源、视觉风格和手机适配。
目标 + 材料 + 风格 + 使用场景
03 / PRACTICE · 02 ITERATE

第二步：不是一次生成就结束

继续补充

“把这些图片插入进去”

AI 把 7 张科普图和 2 张提示图加入现有网页，并重新上线。

出现问题

图片丢了，重新上传

临时文件被系统清理，AI 无法读取；补齐材料后继续修改。这才是真实的协作过程。

补材料 → 看结果 → 发现问题 → 再修正
03 / PRACTICE · 03 PUBLISH

第三步：做出来，还要让别人打开

一句话提出交付要求：新建仓库、开启 Pages、把网址发回来。

LIVE / HTTPS打开真实网页 ↗ niuchen476-svg.github.io/typhoon-safety-guide/
生成成功 ≠ 可以交付
03 / PRACTICE · REVIEW

这个网页，到底是谁做的？

我负责的

  • 发现一个真实的安全教育需求
  • 决定受众、内容来源和页面气质
  • 补充图片，检查内容是否完整
  • 提出“必须上线、别人能打开”

AI 负责的

  • 读取材料并拆成网页结构
  • 写前端代码、适配电脑和手机
  • 插入图片、修改样式和内容
  • 创建仓库、部署并检查链接
说清需求
给足材料
先做一版
检查补充
交付给人
AI 让制作变快；真正决定网页有没有用的，是需求、材料、判断与交付。

PART FIVE / MY VIEW

关于 AI 的思考
始终是人本

AI 越强，人的判断、协作与情感连接越重要。技术应该从真实需求出发，而不是制造伪需求。

CHAPTER 05
05 / MY VIEW

AI 越强，越需要回到人

MY CONCLUSION

AI 再厉害，
也始终是工具。

它可以改变工作方式、提高效率、辅助学习与创造；但真正决定一件事有没有价值、能不能办好的，仍然是人。

01

人与 AI：学会协同

理解工具的能力边界，把机械工作交给 AI，把判断和责任留给自己。

02

人与人：连接更加重要

当效率不再稀缺，沟通、协作、相互理解以及真实的情感连接，反而更难被替代。

03

人与需求：先问是否真实

不要为了追赶技术热潮而硬凑场景、制造伪需求；先理解问题，再决定是否使用 AI。

技术的意义，不是让我们远离人，而是帮助我们更好地理解人、连接人、服务人。
AI 放大人的能力，价值仍由人决定。
